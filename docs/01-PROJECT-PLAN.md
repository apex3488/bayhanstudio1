## 1. Творческая концепция

**Идея: «Precision in the dark».** Сайт — это тёмная студия-лаборатория, где один объект освещён точно и намеренно. Робот-скульптура — не персонаж, а _инструмент_: сенсорная голова, собранная из инженерных пластин, которая «наблюдает» за посетителем и подсвечивает то, что важно. Синий — это свет сенсора, а не краска: он появляется там, где система «смотрит».

Ключевые принципы:

1. **Один источник света — одна мысль.** В каждой секции есть ровно один акцент синего (сенсор, линия прогресса, активный CTA).
2. **Инженерная типографика.** Крупный гротеск для заявлений + моноширинные метки как технические аннотации (`01 / SERVICES`). Никаких декоративных линий без функции.
3. **Ясность сначала.** Через 3 секунды посетитель понимает: кто вы, что делаете, как связаться. Эффекты — второй слой.
4. **Честность.** Ни одной цифры, отзыва, клиента или награды, которых нет.

## 2. Робот: три подхода

| Критерий           | A. GLB/GLTF модель                                                                             | B. Процедурная сцена Three.js                                                                               | C. Статичный визуал + CSS                                               |
| ------------------ | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Визуальный потолок | ★★★★★ (скульптинг, бевели, запечённый AO)                                                      | ★★★★ при сильной арт-дирекции (абстрактная «механическая голова» из пластин, физ. материалы, env-отражения) | ★★★ (зависит от исходного рендера)                                      |
| Наличие сейчас     | **Модели нет.** Нужен 3D-художник или бюджет; стоковые модели — риск лицензии и «узнаваемости» | Создаётся кодом в рамках проекта, лицензия ваша                                                             | Изображение можно **отрендерить из сцены B** — тогда лицензия тоже ваша |
| Размер ресурсов    | 0.5–3 MB (Draco/Meshopt + KTX2-текстуры)                                                       | ~0 KB ассетов, только JS (three + r3f ≈ 200 KB gzip, лениво)                                                | 40–120 KB AVIF/WebP                                                     |
| Производительность | Средняя–высокая нагрузка, зависит от полигонажа                                                | Контролируемая: мало полигонов, без текстур, инстансинг                                                     | Минимальная                                                             |
| Сложность          | Моделирование вне проекта + оптимизация пайплайна                                              | Высокая на арт-дирекцию, средняя по коду                                                                    | Низкая                                                                  |
| Бесплатность       | Только если создавать самим / CC0 с проверкой                                                  | Да                                                                                                          | Да                                                                      |

### Рекомендация (гибрид B → C, с готовностью к A)

1. **[О] B — процедурная «Sentinel Head»**: абстрактная голова из ~20–40 фрезерованных пластин (Extrude/RoundedBox геометрии с фасками), визор-щель с эмиссивным синим сенсором, `MeshPhysicalMaterial` (metalness, clearcoat, anisotropy), отражения из `RoomEnvironment` через PMREM (без загрузки HDR-файла), 3 источника света (ключевой холодный, контровой синий, слабый заполняющий). Взаимодействие: голова и «зрачок» сенсора отслеживают курсор с инерцией; на скролле пластины раздвигаются (разборка → сборка) в переходе к манифесту.
2. **[О] C — постер-fallback**: рендер той же сцены, снятый в высоком разрешении нашим же кодом, экспортируется в AVIF/WebP. Используется: до загрузки WebGL (без скачка layout), при отсутствии WebGL, при `prefers-reduced-motion`, при `Save-Data`/медленной сети и на слабых устройствах. CSS-реакция: лёгкий параллакс и подсветка за курсором.
3. **[Н] A — позже**: компонент сцены изолирован за интерфейсом `RobotModel`, поэтому при появлении авторской GLB-модели её можно подключить без переписывания hero.

Честное ограничение: процедурная голова не достигнет уровня скульптинга в Blender. Если для вас критичен «фотореалистичный» робот — нужен 3D-художник (решение §12, вопрос №4). Первый визуальный прототип сцены я покажу на этапе C до полировки, чтобы вы оценили, устраивает ли уровень.

## 3. Карта страниц и сценарии

Многостраничный статический сайт, **каждая страница пререндерится в собственный HTML** → прямое открытие и обновление работают на GitHub Pages без хаков.

```

/{lang}/                  → Главная: Hero · Manifesto · Services · Process · Why BAYHAN · Contact CTA · Footer

/{lang}/contact/          → бриф-форма + прямые каналы
/{lang}/privacy/          → [Ж] короткая политика (что форма делает и не делает с данными)
/404.html                 → трёхъязычная страница «не найдено» со ссылками
{lang} = ru | en | uz      → итого 27 страниц + корень + 404
```

- **[О]** Отдельные страницы услуг: дают SEO по запросам («разработка telegram бота ташкент» и т.п.), глубокие ссылки для рекламы/постов и короткий путь «услуга → бриф с предвыбранным типом проекта».
- Страница услуги: hero направления · что входит · бизнес-ценность · как проходит работа · CTA «Обсудить» → `/contact/?type=bots` (тип предзаполнен).
- **Портфолио не добавляется** (по брифу).

### Пользовательские сценарии

1. **Быстрый контакт:** Главная → CTA «Написать в Telegram» в hero/хедере → t.me/APEX348. ≤ 1 клик.
2. **Осознанная заявка:** Главная → Services → страница услуги → «Обсудить» → бриф (тип предзаполнен) → предпросмотр текста → Telegram с готовым сообщением.
3. **Пришёл из поиска на услугу:** страница услуги (полноценная, без зависимости от главной) → бриф.
4. **Смена языка:** переключатель в хедере ведёт на **ту же страницу** в другой локали.
5. **Без WebGL / reduced motion / медленная сеть:** весь текст, навигация и форма работают; вместо 3D — постер.
6. **Instagram/канал:** в футере и на Contact; канал — как «следить за студией», не как основной CTA.

## 4. Архитектура (кратко, подробно — в 02-ARCHITECTURE.md)

- **Vite + React 19 + TypeScript**, **SSG собственным скриптом пререндера** (`react-dom/server` → HTML на каждую комбинацию маршрут × язык), затем `hydrateRoot` на клиенте.
- **MPA, без клиентского роутера**: каждая страница — реальный HTML. Переходы между страницами — нативные кросс-документные View Transitions (`@view-transition`), где поддерживаются; в остальных браузерах — обычная навигация.
- **Контент отделён от представления**: тексты в `src/content/{ru,en,uz}.ts` с общим типом → отсутствующий ключ ломает `tsc`, а не продакшен.
- **3D изолирован** в лениво загружаемом чанке (`React.lazy` + dynamic import), грузится после первого рендера и только если устройство подходит.
- **Один WebGL-контекст** на страницу (только главная и, опционально, страницы услуг в облегчённом виде).

### Типографика (бесплатные, OFL, с кириллицей)

- **Display:** Unbounded (variable) — широкий геометричный гротеск, сильный характер для заголовков. Альтернатива: Geologica.

- **Метки:** Manrope uppercase с трекингом. JetBrains Mono отклонён на этапе B: на русских страницах он добавлял ~50 KB и выводил шрифты за бюджет.
- ⚠️ Проверить наличие глифа **ʻ (U+02BB)** для узбекских oʻ/gʻ во всех трёх шрифтах; при отсутствии — фолбэк-шрифт на этот символ через `unicode-range`.

## 7. Motion-система

### Токены

| Токен        | Значение                                | Применение                 |
| ------------ | --------------------------------------- | -------------------------- |
| `dur.micro`  | 160 ms                                  | hover, фокус               |
| `dur.ui`     | 320 ms                                  | меню, переключатели, форма |
| `dur.reveal` | 720 ms                                  | появление блоков           |
| `dur.hero`   | 1400 ms                                 | раскрытие hero             |
| `ease.out`   | `expo.out` / `cubic-bezier(.16,1,.3,1)` | появления                  |
| `ease.inOut` | `power3.inOut`                          | переходы, сборка робота    |
| `stagger`    | 60 ms (слова), 90 ms (блоки)            |                            |

### Правила

- Появление: снизу вверх 24px + opacity, один раз; текст никогда не скрыт без JS (начальные стили применяются только после гидрации — без «пустой страницы»).
- **Preloader [О]:** вордмарк BAYHAN собирается из штрихов; **максимум ~1.2 с**, не ждёт 3D, показывается один раз за сессию (`sessionStorage`), при reduced motion не показывается.
- Hero: кинетический заголовок по словам (SplitText с сохранением доступного текста), затем подзаголовок и CTA, робот проявляется светом.
- Робот: инерционное слежение за курсором (lerp), на тач-устройствах — медленный «idle scan», реакция на скролл.
- Магнитные CTA и курсор-подсветка: **только `(hover: hover) and (pointer: fine)`**. Системный курсор не скрывается; кастомный элемент — лишь дополнительный слой, исчезает при touch.
- Переходы страниц: [Ж] View Transitions (затемнение + сдвиг заголовка).
- **Звук [Н]:** выключен по умолчанию, кнопка в хедере, тихий короткий эмбиент + клик; загрузка аудио только после включения. Предлагаю отложить до финала.
- **Reduced motion [О]:** без скролл-скраба, параллакса, слежения, preloader; контент появляется мгновенно; робот — статичный постер. Управляется через `gsap.matchMedia()`.
- Мобильные: короче анимации, без pin-секций при высоте < 600px, без тяжёлых scrub.

## 8. Адаптивность и производительность

Брейкпоинты: 360 · 480 · 768 · 1024 · 1440 · 1920+. Проверка на 375×812, 768×1024, 1440×900, 1920×1080, ландшафт мобильного.

**Стратегия загрузки 3D:**

1. HTML с текстом и постером приходит сразу (пререндер) → LCP = заголовок или постер, не canvas.
2. После `load` + `requestIdleCallback` проверяем: WebGL2 доступен, нет reduced motion, нет `Save-Data`, `deviceMemory` ≥ 4 (если доступно), не `2g/3g` → грузим 3D-чанк.
3. Canvas плавно заменяет постер того же кадрирования (без CLS).

**Рендер:** DPR ≤ 1.75 (мобильные ≤ 1.5), адаптивное снижение DPR при просадке FPS, `frameloop="demand"`/пауза вне вьюпорта и при скрытой вкладке, без теней в реальном времени (запечённый контактный градиент), ≤ 60k треугольников, общие материалы, `dispose` при размонтировании, обработка `webglcontextlost`.

**Бюджеты (цели, не обещания):** начальный JS без 3D ≤ ~120 KB gzip; 3D-чанк ≤ ~250 KB gzip; шрифты ≤ ~150 KB (subset, `woff2`, `font-display: swap`, preload 1–2 файлов); постер ≤ 80 KB AVIF. Lighthouse и CWV измеряем на production-сборке и исправляем реальные проблемы.

**Доступность (WCAG 2.2 AA):** семантика (`header/nav/main/section/footer`, один `h1`), skip-link, видимый фокус (2px синий outline + offset), `aria-label` у иконок, `aria-live` для статуса формы, ошибки полей связаны через `aria-describedby`, сенсорные цели ≥ 44×44, масштаб 200% без потери контента, canvas `aria-hidden` + текстовое описание не нужно (декоративный).

## 9. Локализация

- Языки: `ru`, `en`, `uz` (узбекский, **латиница**, корректные oʻ/gʻ через U+02BB).
- **URL — источник истины** (`/ru/...`). Это даёт корректный `<html lang>`, SEO, отдельные `title/description`, `hreflang`-альтернативы и `canonical` на каждой странице.
- Словари: `src/content/{ru,en,uz}.ts`, тип `Dictionary` из базового языка — отсутствующий ключ = ошибка компиляции. Fallback во время выполнения не нужен; на случай необязательных полей — fallback на EN с предупреждением в dev-консоли.
- Переводится всё: навигация, hero, услуги, CTA, форма, ошибки, состояния загрузки, footer, meta, OG, 404, alt-тексты, aria-лейблы, текст сообщения в Telegram.
- Переключатель: ссылки `<a hreflang>` на ту же страницу в другой локали (работает без JS).
- Корень `/`: [Ж] выбирает язык по сохранённому выбору → `navigator.languages` → язык по умолчанию; показывает ссылки на все 3 языка (работает без JS, корректен для поисковиков).
- Хранение выбора: **[Ж] один ключ `localStorage`** только для корня; обёрнут в try/catch. Cookies не используются. Если вы против — убираем, остаётся автоопределение.
- ⚠️ Тексты на узбекском и русском требуют вычитки носителем перед запуском.

## 10. Форма заявки (статический сценарий)

Поля:

| Поле                          | Тип                                             | Обязательно |
| ----------------------------- | ----------------------------------------------- | ----------- |
| Имя                           | text, ≤ 60                                      | да          |
| Тип проекта                   | radio-группа: 5 услуг + «Другое / пока не знаю» | да          |
| Краткое описание              | textarea, 20–1000 символов, счётчик             | да          |
| Бюджет                        | select диапазонов + «Обсудим»                   | нет         |
| Предпочтительный способ связи | Telegram / Instagram                            | да          |

Сценарий:

1. Валидация на клиенте, понятные ошибки на языке страницы.
2. **Предпросмотр**: показываем ровно тот текст, который будет передан.
3. Кнопка **«Скопировать и открыть Telegram»**: копирует текст в буфер (Clipboard API, fallback — выделенный textarea) и открывает `https://t.me/APEX348?text=<encoded>`. Если клиент не вставил текст — подсказка «Текст скопирован, вставьте его в чат».
4. Для Instagram: копирование + ссылка на профиль (DM в Instagram нельзя предзаполнить).
5. Финальный статус честный: «Telegram открыт с готовым текстом. **Отправьте сообщение**, чтобы мы его получили.» — никаких «заявка принята».
6. Никаких данных не уходит на наш сервер (его нет), нет аналитики, нет хранения → Privacy Policy формально не обязательна, но [Ж] короткая страница с объяснением повышает доверие.

Будущее [Н]: отправка через собственного Telegram-бота требует backend (serverless) — токен нельзя хранить в клиенте. Только после отдельного согласования.
